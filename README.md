# Ink Trio

[![test](https://github.com/m-masaki72/ink-trio/actions/workflows/test.yml/badge.svg)](https://github.com/m-masaki72/ink-trio/actions/workflows/test.yml)

三色のインクを重ねて、色校正と同じ配色をつくる 5×5 パズル。

**▶ [ここで遊べます](https://m-masaki72.github.io/ink-trio/)**

![盤の上に日刊・練習・自由・時間走のタブ。左が目標の配色「色校正」、右が自分で押す「刷り台」。残り手数と次に乗るインクが下に出る](docs/play.png)

## 遊び方

- 盤のマスを**左クリック**すると、そこを中心とした 3×3 にインクが乗る（盤の外へ出た分は切り落とし）
- 乗るインクは押すたびに **マゼンタ → イエロー → ブルー** の順で循環する
- 重なりは XOR。同じインクを二度重ねると打ち消し、三色そろうと白になる
- 押せるのは**最短手数まで**。使い切ったら「一手もどす」で戻してやり直す
- 行き詰まったら「別の課題」で引き直せる（練習中は「この面をやり直す」になる）
- 左の「色校正」と同じ配色にできたら完成

![3手で揃えたところ。校了の判が押され、3秒後に次の課題へ移る](docs/done.png)

## 置き方

ビルドはありません。リポジトリの中身をそのまま置けば動きます。サーバー側の処理も不要です。

- 静的ホスティング（GitHub Pages、Netlify、Cloudflare Pages など）にそのまま置く
- 手元で見るときは簡易サーバを立ててください（`python3 -m http.server` など）。
  JS を ES モジュールに分けているため、`file://` で直接開くとブラウザが読み込みを拒みます

## 日刊号と時間走

盤の上のタブで **日刊 / 練習 / 自由 / 時間走** を切り替えます。

- **日刊** は毎日 5 問。難易度の型は 3手・6手・6手・10手・10手 で固定です
- 出題は日付から決まるので、**同じ日は誰が開いても同じ 5 問**になります
- 号は消えません。「前の号」でさかのぼって、過去の号はいつでも遊べます
- 所要時間は計りますが、**計り始めるのは最初の一手から**です。盤を読む時間は計りません
- 5 問そろえると結果を写せます。共有テキストは色ではなく、この作品自身の数字表記（0〜7）です

**時間走** は 5 分で 10 手の課題を何問さばけるかを競うモードです。

- 出題は毎回プールから引くので、**同じ並びは二度と来ません**。事前に用意して臨むことができません
- 行き詰まったら「パス」で次へ。パスした問は走り終えたあとに見直せます
- 記録に残せる走行は **1 日 3 回** まで。それ以降は練習走行になります
- 5 分待たずに「やめる」で切り上げられます。そこまでの結果は記録されます

![日刊のタブ。第◯号と「1 / 5問目」、経過時間が盤の上に出る](docs/daily.png)

![時間走の走行中。残り時間と解けた問数、「パス」と「やめる」が盤の上に出る](docs/rush.png)

記録は端末の中だけに残ります。外部への送信はありません。

## ホーム画面に入れて遊ぶ

Service Worker を持たせてあるので、一度開けば**圏外でも遊べます**。ブラウザの
「ホーム画面に追加」「アプリとしてインストール」から入れると、縦向きの単独窓で開きます。

外部への送信が無いのは通常どおりで、取り込むのは自分のファイルだけです（書体だけは
別オリジンなので取り込まず、圏外では端末の既定書体に落ちます）。

**中身を差し替えたら `sw.js` の `CACHE` の版を上げてください。** 上げないと、
すでに入れた人には古い一式が出続けます。配るファイルの一覧も `sw.js` に手で並べてあるので、
`src/` にモジュールを足したらそこにも足します（入れ忘れは `tests/pwa.test.js` が捕まえます）。

絵柄を変えるときは `icons/*.svg` を直してから焼き直します。

```sh
node tools/make-icons.mjs
```

## テスト

単体テストは Node 標準のランナーだけで走ります（依存なし）。E2E は実ブラウザで確かめます。

```sh
npm run dev                          # 手元で見る（http://localhost:8000）

npm test                             # 単体。依存も install も不要
node --test tests/rules.test.js      # 1ファイルだけ

npm ci && npx playwright install     # E2E の準備（初回だけ）
npm run test:e2e                     # E2E（Chromium / Firefox / WebKit）
npx playwright test e2e/play.spec.js # 1ファイルだけ
npm run test:all                     # 両方
```

| 層 | 検査するもの |
|---|---|
| 単体 `tests/` | 盤の規則、最短手数の算出、出題の保証、保存値の検証、配色の不変条件、集計、日刊号の再現性、時間走の勘定、共有テキスト、配るファイルの一覧と実物の食い違い |
| E2E `e2e/` | 遊びの流れ（押す・戻す・使い切り・校了・自動遷移）、表示設定と保存、キーボード操作、壊れた保存値、保存不可環境、CSP、モジュールの読み込み、狭い画面、圏外での起動と操作、日刊号の進行と記録、時間走の走行 |

## 道具

どれもビルド工程ではありません。中身を変えたときだけ手で回します。

```sh
npm run icons          # icons/*.svg から PNG を焼く（意匠を変えたとき）
npm run shots          # docs/*.png を撮り直す（画面が変わったとき）
npm run check:public   # 公開して困るものが履歴に混ざっていないか調べる
npm run pack:itch      # itch.io 用の zip を作る（dist/ink-trio-itch.zip）
```

`npm run pack:itch` は配るファイルを **`sw.js` の取り込み一覧から導きます**。圏外用の
一覧が「遊ぶのに要るもの全部」なので、二つ目の一覧を作らないためです。組んだあと
itch の配り方（別オリジンの iframe・深いサブパス）を模して、盤が組まれて実際に解けるか・
Service Worker の範囲・コンソールのエラーまで見てから zip にします。掲載の設定と
文面は [docs/itch.md](docs/itch.md) にあります。

`npm run shots` は簡易サーバを自分で立て、押す手順まで込みで写真を作ります。
手で撮ると「どの面のどこを押した写真か」が失われて再現できなくなるためです。

`npm run check:public` は現在のツリーではなく **git 履歴の全オブジェクト**を見ます
（消したファイルも履歴には残るため）。鍵らしき文字列、手元の絶対パス、ファイル内の
メールアドレス、危ない名前のファイル、PNG に付いた撮影機材や位置情報を調べ、
コミットの著者（GitHub で公開されます）を最後に出します。
固有の識別子も見たいときは、リポジトリに書かずに渡します。

```sh
EXTRA='社内ID|ホスト名' npm run check:public
```

## 外部からの読み込み

書体のみ Google Fonts から読んでいます（Zen Kaku Gothic New）。
オフラインで使う場合、読み込みに失敗しても端末の既定書体に落ちるので動作に影響はありません。
完全に自己完結させたい場合は `<head>` の `<link rel="preconnect">` と
`<link href="https://fonts.googleapis.com/...">` の 3 行を削除してください。

## 進行度の保存

localStorage に `inktrio.v1` というキーで保存します。保存されるのは以下だけです。

- 練習の到達面数と達成した面
- 難易度ごとの通算クリア数、今日ぶんのクリア数と日付
- 表示設定（目印・画面・配色・音）と選択中の難易度

外部への送信は一切ありません。保存領域が使えない環境では静かに諦め、その旨を画面に表示します。
「表示設定 → 記録 → 記録を消す」で全て削除できます。

## 表示設定

| 項目 | 内容 |
|---|---|
| 目印 | 色以外で配合を示す方法。帯／記号（M・Y・B）／数字（0〜7）／なし |
| 画面 | ブラウン管風の走査線と発光／フラット |
| 配色 | ビビッド／パステル |
| 音 | Web Audio で合成。外部音源なし |
| 補助 | ズレを示す（保存される）／答えを見る（課題ごとに閉じる） |

配色は一般色覚・P型・D型・T型の 4 通りで最小 ΔE が最大になるよう数値最適化し、
インクが乗った 7 色の明度が等間隔の階段になるよう配置しています（白紙だけがその階段より
大きく下に離れており、乗っているか否かが一目で分かります）。文字コントラストは全要素で
WCAG AA を満たします。

読み上げでは、盤のマスが「3行2列 パープル」のように位置と配合を名乗ります。色以外の目印
（帯・記号・数字）は見た目のためのものなので、読み上げには混ざりません。

![目印を「記号」にしたところ。各マスに M・Y・B が並び、含まれるインクだけが濃く出る](docs/marks.png)

![配色をパステル、画面をフラットにしたところ](docs/pastel.png)
